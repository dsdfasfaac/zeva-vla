## 本轮可证伪假设

原 ZeVA flow 训练项来自 PI05Policy 对 EEF16 的整段 H50 均值，而 RoboTwin 只执行前 H15 后重规划。因此本轮保持 PI 的 H50 输出、数据/相机/动作协议不变，只使 ZeVA residual-on 的 connected flow 梯度来自同一次 PI 前向的前 H15；Base residual-off 仍用普通 H50 flow。我们在已训练的 Base1000 上新建 ZeVA adapter/optimizer，并将 action-expert LR 设为 **0**，所以本轮允许 ZeVA 额外训练，而不会把 Base 的参数漂移混进比较。Stage1 ZTE/Mamba、train95 bank、task-language 检索和真实 H15 recurrent phase 仍照常进入 ZeVA；VLM 冻结。

实现没有再次运行 PI 来拼接 H15 损失：在 `torch.compile` 后包裹 PI05 core 的 `forward`，捕获同一次实际前向返回的带梯度 `[B,50,D]` 原始 flow error，验证其 EEF16/H50 归约与原 PI05Policy H50 输出一致，再取前 H15/EEF16 的均值作为 ZeVA flow 主项。原 sampled H50 preserve hinge 暂时保留；Gaussian NLL、prior dropout0.4、gate、独立梯度裁剪与双残差位置不变。训练日志单列 `train_flow_h15`，避免将 H50 记录误认成优化目标。该设计尚不证明 H15 离线改善会提升闭环成功率。

训练前单元测试 7 项通过。四卡真实 TorchCodec/`torch.compile` global256 单步检查在 aigc29 完成 `SMOKE_COMPLETE`，没有写模型 checkpoint；第一轮检查被旧校验的“AE LR 必须正数”拒绝，未进入优化步，随后仅对显式 Base-locked H15 模式放开 LR0 并重新检查通过。独立源码快照：`/mnt/100T/users/dingxin/VLA/h15-route-test-20260916-19B9I7`；通过的 smoke：`/mnt/100T/users/dingxin/VLA/zeva-runs/robotwin-v5-h15-tasklang/h15-route-smoke-20260916-a29-v2/h15_route_smoke`。失败的首次 smoke 原日志保留于相邻的 `h15-route-smoke-20260916-a29`。

## 决策和交付

对固定 500/1000 步分别做同 5874 条 validation5、同噪声/顺序的 H15 residual-on、own-off、固定 Base 三方对照；按预注册规则选择最早同时胜过两个对照的 checkpoint。两者都不满足则不进入正式测试，也不回头根据成功率挑倍率。若离线门槛通过，复用已冻结的 10×20 expert-valid seed/seen instruction manifest，严格同条件做 Base 与 ZeVA 闭环，核对视频、每任务成功数、总成功率及配对不确定性。必须另外报告 Base 的绝对成功率：此前 Base1000 正式结果为 55%，低于历史 57% 参考线，不能仅凭相对提升掩盖这一点。

选模由 [`select_h15_route_candidate.py`](../scripts/robotwin_eval/select_h15_route_candidate.py) 执行，而不是人工读测试表。它强制要求两份完整的 500/1000 步只读报告、同一 5874 条样本顺序 SHA、同一固定 Base、原始 gate、模型权重与 Base 字节相同、训练 manifest 明确声明 AE LR0/ZeVA H15 梯度分路；按最早通过 H15 on<off 且 on<Base 的 checkpoint 输出选择记录。四项合成正反测试已通过。[1000 步完整原门控报告](results/robotwin-h15-route-20260916/validation_diagnostics_001000.json)显示 H15 on `0.01005738880`、off/Base `0.01009312179`，改善约 `0.35%`。两步均通过最低离线门槛；[预注册选择记录](results/robotwin-h15-route-20260916/h15_candidate_selection.json)选择**最早通过的 500 步**，没有事后改成选择数值稍好的 1000 步。离线微弱改善不能证明闭环 +4pp。

500步 checkpoint 已由训练器通过 `latest.json` 发布（完整模型/adapter/optimizer文件），[`run_h15_route_step500_diagnostic.sh`](../scripts/robotwin_eval/run_h15_route_step500_diagnostic.sh) 在独立 GPU4 完成全量只读验证，不占用训练 GPU0–3。[完整 500 步原门控报告](results/robotwin-h15-route-20260916/validation_diagnostics_000500.json)已归档。5874 条 validation5 决策、368 batches、同一噪声/样本顺序下，H15 residual-on flow `0.01006796956`，own-off 和固定 Base 都为 `0.01009312179`，改善 `0.00002515229`（约 `0.25%`），胜出决策比例 `0.5337`。Base `model.safetensors` SHA 与固定 Base 字节相同。这个微弱离线改善满足预设的严格小于门槛，但远不足以证明正式成功率会多 4 个百分点。

同一报告中，H15 context 注入相对 noisy action embedding 的均值范数约 `0.00675`，prior 注入仅约 `0.0000165`；因此当前效果主要来自 ZTE context，Gaussian action-prior 分支几乎没有实际注入。作为**不参与本轮预注册选模**的机制检查，在相同 validation5 上仅将 context gate 临时设为 2 倍、prior 保持原值：[全量敏感性报告](results/robotwin-h15-route-20260916/validation_diagnostics_000500_ctx2_prior1.json)的 H15 flow 变为 `0.01007821783`，**比原门控的 `0.01006796956` 更差**；胜出决策比例由 `0.5337` 降为 `0.5129`。因此“ZTE 信息有用，只是注入太弱，直接放大即可”的简单假说被这次离线检查否定。这个检查不修改 checkpoint、不使用闭环测试标签，也不改变原门控选模规则。1000步的原 gate 诊断仍由原训练控制器执行。

闭环评测节点是独立的硬条件。[节点健康记录](ROBOTWIN_H15_EVAL_HOST_READINESS_20260916.md)现已更新：aigc29 通过隔离补齐缺失的 EGL/Vulkan 用户态库，8 张卡逐卡通过正式 SAPIEN 钩子有限帧、物理 PID/PCI 映射与干净退出检查；a28 仍由他人占用，a24/a31 仍阻断。**通过节点健康检查只允许开始评测，不是成功率结论。**

若本轮仍不过关，下一步先量化实际更新而不是继续加步数：此前 32 条训练决策的[梯度诊断](ZTEV2_OBJECTIVE_GRADIENTS_20260915.md)显示加权 NLL 对部分共享模块的原始梯度远大于 flow；本轮已经切断 NLL 到共享 task/context 的梯度，但 ZeVA 参数仍共同按范数 1.0 裁剪，prior head 的 NLL 可能影响 flow 分支的裁剪比例。**这只是机制假设，不可由原始梯度范数推出 Adam 更新或闭环因果结论。** 如验证 H15 失败，应在固定训练批次上测裁剪前后各模块实际梯度和参数更新，再决定是否分组裁剪、降低/移除辅助 NLL，或重训更直接预测 Base 动作误差的 ZTE 表征。
