## 固定方法

现有 effect prefix 定义为 BIT，保持已验证 CTE+BIT+EAP 路径不变。PIM 是同一 episode 内跨 attempt 的 BIT trace；attempt reset 提交，episode reset 清空。第一 attempt 无 PIM，必须与 parent policy 完全一致。

离线配对只使用 train95，不读取 success label：同任务同条件初始 CTE phase 最近邻50%、同条件远邻20%、跨条件最近邻10%、PIM-off 20%。历史源必须与当前样本来自不同 episode。

## 冻结 validation5 gate

训练完成后先在冻结 validation5 的 5,874 个决策上，以逐决策共同扩散噪声检查 parent、PIM aligned、同任务完整错位和 PIM-off。结果产生前固定 gate 为：`PIM-off <= parent`、`aligned <= parent`、`aligned < shuffled`、`aligned <= PIM-off`。第一项检查第一 attempt 的动作误差非退化；结构上的空 PIM 等价已由单元测试覆盖。离线 gate 通过后才运行与正式集合不相交的多-attempt paired 开发闭环；不得用正式测试标签选择 checkpoint、seed、任务或 gate，且离线 MSE 不是成功率。

固定 step2000 已完成 5,874/5,874 决策审计并通过全部 gate：parent `0.0086122569`、aligned `0.0080868378`、同任务 shuffled `0.0081062032`、PIM-off `0.0080908216`。aligned 相对 parent 改善约 `6.10%`，但相对 PIM-off 和 shuffled 的 PIM 专属差异分别只有约 `0.049%` 和 `0.239%`；必须由多-attempt 闭环判断实际价值，不能将该离线差异写成成功率提升。

## 预声明 multi-attempt 开发 gate

使用从 absolute seed `2000000` 起每任务最早 8 个 expert-valid seed，且与原冻结正式集和已使用的 epoch40 开发集逐任务零交叉。Base、无 PIM parent 和 PIM 共享相同 seed、seen instruction、场景初始化、连续扩散 RNG 策略和最多 4 次 attempt 预算。第一次均执行 episode reset；失败后 Base/parent 继续 episode reset，PIM 执行 attempt reset 并提交上一 attempt 的 BIT trace。成功后立即停止该 episode，保存每个实际执行 attempt 的视频。

在读取任何新闭环 success label 前固定开发 gate：PIM 第一次 attempt 成功数不低于 parent；第 4 次累计成功数至少比 parent 多 4/80；seed/instruction、逐 attempt 轨迹、视频和停止条件审计完整。Base 仅作为诊断参照。该开发 gate 不允许触发新的原冻结 formal 重跑；原正式集合已经产生无 PIM 结果，后续 PIM 方法若进入正式评测必须另行明确一次性协议。

## Multi-attempt 开发结果

冻结的新 10×8 manifest SHA256 为 `1fe1df3cf4a2b3f4b7fc4707233e376df2e51b64a4ee7cb296f7c9a7ad34ed84`，与原正式 manifest 和此前 epoch40 开发 manifest 均逐任务零交叉。Base、parent、PIM 分别产生 169、151、165 个实际执行 attempt 视频，完整覆盖 80 个 episode。

- Base：attempt1/2/3/4 累计 `39/54/58/62`，最终 `62/80=77.5%`。
- CTE+BIT+EAP parent：累计 `44/62/63/67`，最终 `67/80=83.75%`。
- CTE+BIT+PIM+EAP：累计 `43/51/61/69`，最终 `69/80=86.25%`。

PIM 相比 parent 最终多 `2/80=+2.5pp`，但第一次 attempt 少 1 次成功，且最终增益未达到预声明的 `+4/80`。因此 multi-attempt 开发 gate **FAIL**；不得把该结果表述为 PIM 已验证提升，也不得据此进入新的正式测试或从中间 checkpoint/正式标签继续挑选。PIM 相比 Base 的 `+7/80` 不是 PIM 的净贡献，因为 parent 自身已经是 `+5/80`。
